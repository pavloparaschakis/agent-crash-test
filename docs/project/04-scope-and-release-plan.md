# Scope and Release Plan

## Scope rule

Every new feature must answer: does this help a maintainer reproduce, understand, fix, or prevent agent-tool failure? If not, it belongs in the parking lot.

## Release 0: private prototype

**Objective:** Prove that response perturbation and state-diff assertions produce failures people understand and can fix.

**Included:**

- TypeScript CLI skeleton.
- One local MCP demo server.
- Three mutations: timeout, malformed response, duplicate call.
- One stateful scenario that catches an unintended extra side effect.
- Terminal report.
- Ten hand-authored fixtures.

**Exit criteria:**

- Five people who did not build it can complete the demo.
- At least 80% understand the failure without oral explanation.
- At least three failures lead to an obvious code or schema fix.

## Release 1: public MVP

**Objective:** Become a useful local crash-test pack tool for MCP maintainers, with a reproducible fault/effect/recovery loop and a small deterministic runner.

**Included:**

- stdio-only local transport support, frozen to a documented MCP baseline.
- Pack authoring and deterministic rerun, not arbitrary-session recording.
- Six mutation classes, with a stable extension point for twelve.
- Portable YAML fixture format.
- Behavioral assertions.
- Stateful fixture oracle for intended and forbidden side effects.
- Terminal, Markdown, and JSON reports.
- GitHub Action and uploaded report artifacts; PR comments follow once the report-diff model is stable.
- Demo server and public fixture corpus.
- Security and redaction defaults.
- Contributor documentation.

**Excluded:** Hosted SaaS, mandatory model judging, production scanning, A2A, desktop-app integrations, automatic code commits, remote authenticated HTTP, arbitrary desktop-agent recording, JUnit/SARIF/HTML reporting, and generic state introspection.

**MVP release gate:** All P0 requirements in [the PRD](03-prd.md) pass, the quickstart can be completed on macOS, Linux, and Windows, and the demo catches at least one “requested action succeeded but an extra action also occurred” failure.

## Release 1.1: shareable quality layer

- Static compatibility cards.
- README badge endpoint generated by CI artifacts.
- Version-to-version diff mode.
- Local unauthenticated Streamable HTTP.
- Protocol-aware recording proxy and import adapters.
- Test minimization.
- Better remediation suggestions.
- More popular server examples using mocks or sandboxes.
- Additional mutation packs contributed by the community.
- JUnit XML, SARIF, and static HTML reporters.

## Release 2: ecosystem layer

- Pluggable client adapters.
- Local model adapters.
- A2A and Agent Skills adapters.
- Community challenge mode.
- Public opt-in benchmark index.
- Maintainer dashboard as a static artifact first.

## Explicit cuts if schedule slips

Cut in this order:

1. LLM judge.
2. Hosted index.
3. Client adapters.
4. Auto-fix patch generation.
5. Advanced HTML visualization.

Never cut:

1. Deterministic fixtures.
2. Fault injection.
3. Behavioral assertions.
4. Stateful side-effect assertions in the demo and fixture format.
5. Reproduction output.
6. GitHub Action.
7. Safe defaults.

## Release quality levels

### Experimental

API may change; fixtures are not stable; reports are for local use.

### Beta

Fixture schema is versioned; CLI has migration guidance; CI action is usable by external repositories.

### Stable

Backward compatibility policy, changelog discipline, signed releases, reproducible builds, and documented security response process are in place.
