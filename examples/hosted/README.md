# Self-hosted collaboration service

This example runs the dependency-light Agent Crash Test collaboration API on
your machine. It stores explicitly uploaded, already-redacted `RunResult` JSON
files in a local directory. It has no account system, external deployment,
telemetry, or automatic upload behavior.

## Start locally

Build the project, choose a strong local API token, and start the example:

```bash
npm run build
export ACT_HOSTED_API_TOKEN="replace-with-at-least-16-random-characters"
node examples/hosted/server.mjs
```

The server binds to `127.0.0.1:7411` by default and stores data under
`.agent-crash-test/hosted`. Override these only when needed:

```bash
ACT_HOSTED_PORT=7420 \
ACT_HOSTED_DATA_DIR=/absolute/private/path \
node examples/hosted/server.mjs
```

`ACT_HOSTED_HOST` is intentionally omitted from the normal example. Binding to
a non-loopback interface creates a network service and requires firewall, TLS,
token-distribution, and host-hardening decisions outside this local foundation.

## Upload a report

Pass the path to a JSON `RunResult` generated by Agent Crash Test:

```bash
node examples/hosted/upload-run.mjs .agent-crash-test/demo/example.json
```

The service rejects values that still contain secret-shaped text, sensitive
fields that are not exactly `[REDACTED]`, events/findings without
`redactionApplied: true`, oversized bodies, and malformed report structures.
It never silently redacts an upload because doing so could create false
confidence about what was persisted.

## API

Health is deliberately minimal and does not require authentication:

```bash
curl http://127.0.0.1:7411/health
```

Every `/v1` route requires `Authorization: Bearer $ACT_HOSTED_API_TOKEN`:

```bash
curl -H "Authorization: Bearer $ACT_HOSTED_API_TOKEN" \
  http://127.0.0.1:7411/v1/runs
```

| Method   | Path                | Behavior                                      |
| -------- | ------------------- | --------------------------------------------- |
| `POST`   | `/v1/runs`          | Store one redacted `RunResult` JSON body      |
| `GET`    | `/v1/runs?limit=50` | List newest retained run summaries            |
| `GET`    | `/v1/runs/:id`      | Read a stored run envelope                    |
| `DELETE` | `/v1/runs/:id`      | Permanently delete one stored run             |
| `GET`    | `/health`           | Return process health without storage details |

Uploads use server-generated UUIDs rather than report-controlled filenames.
Files are written to owner-only temporary files, synchronized, and atomically
renamed in the same directory. Run IDs are strictly validated before reads or
deletes.

## Default limits and retention

- Request body: 2 MiB.
- Entries in each top-level report collection: 10,000.
- Retained runs: 1,000; the oldest are removed after a successful upload.
- Retention age: 30 days; expiry is enforced on startup and API access.
- Maximum list page: 100 summaries.
- CORS: disabled.
- Bind address: IPv4 localhost.

Parent CLI code can import `startHostedService()` and retain the returned
handle. Calling `handle.stop()` or `stopHostedService(handle)` is idempotent and
drains active HTTP requests up to the configured shutdown grace period.

## Security boundary

This is a single-token, local/self-hosted foundation—not a multi-tenant control
plane. Anyone holding the token can list, read, upload, and delete all runs in
that service instance. Use a dedicated private data directory, rotate exposed
tokens, leave CORS disabled unless a specific browser origin needs access, and
do not expose the plain HTTP listener directly to an untrusted network.
